🎯 DeepValue 计算逻辑流程

从数据采集到策略生成的完整 Pipeline

1
数据采集 (Ingestion)
从外部数据源拉取历史价格数据（OHLCV），合并多源数据并清洗，写入数据库。
📥 数据源
• Stooq (历史数据)
• yfinance (实时/调整后价格)
• 合并去重、填充缺失
💾 输出表
• prices_raw (原始)
• prices_daily (清洗后)
• 时间范围：过去 6 年
🎯 覆盖范围
MAG7 + QQQ
(AAPL, MSFT, AMZN, NVDA, META, TSLA, GOOGL, GOOG, QQQ)
↓
2
特征计算 (Features)
基于价格历史计算技术指标、波动率、趋势强度等特征，生成 DeepValue Score。
📊 技术指标
• SMA (20/50/200日)
• RSI、MACD、布林带
• ATR (波动率)
🎲 DeepValue Score
综合多因子打分：
• 价格相对位置
• 趋势强度
• 波动率调整
📈 百分位排名
pct_rank_5y：
当前 Score 在过去 5 年的历史分位数
features_daily: symbol, date, deepvalue_score_smooth, pct_rank_5y, rsi, macd, ...
↓
3
支撑/阻力位计算 (Levels)
基于 Swing High/Low 和均线，计算内部结构支撑位 S1/S2/S3 和阻力位 R1/R2/R3。
🔍 候选来源
• swing_5y / swing_1y (历史低点)
• sma20 / sma50 / sma200
• 聚类去重、按强度排序
📐 选择规则
S1: 最近且强度最高
S2: 更深、避免与 S1 太近
S3: 长期防守位
💾 元数据
s_meta (JSON):
记录候选列表、选中原因、强度评分
levels_daily: symbol, date, s1, s2, s3, r1, r2, r3, s_meta, r_meta
↓
3.5
Perplexity 融合 (PP Fusion) 🌐
读取手动保存的 Perplexity 外部支撑位快照，按融合规则调整 S1/S2（S3 不动）。
📂 数据源
本地 JSON 文件
data/external/perplexity_supports/
pp_supports_YYYY-MM-DD.json
🎯 融合策略
S1: Soft-blend (加权平均 + clamp)
S2: 条件替换（仅当内部 S2 弱时）
S3: 不受 PP 影响
⚖️ 权重控制
PP 最大权重: 0.6
置信度阈值: 0.4
derived_level confidence ≤ 0.40
🔑 关键设计：独立外部信号源
• Perplexity 不接收历史价格数据，只基于公开技术分析/研报
• 每天手动保存快照（避免 API 成本 + 保证可复现）
• 融合结果写回 levels_daily.s1/s2 + s_meta.pp_fusion
• 报告会显示 PP 状态/置信度/区间
# 融合后更新 levels_daily UPDATE levels_daily SET s1 = fused_s1, s2 = fused_s2, s_meta = json_set(s_meta, '$.pp_fusion', fusion_meta) WHERE symbol=? AND date=?
外部信号 手动快照 独立决策
↓
4
市场状态 (Market State)
基于 QQQ 的技术指标判断市场风险偏好（risk_on / risk_off），调整仓位乘数。
📊 判断依据
• QQQ 相对 SMA50/200
• RSI 过热/超卖
• 波动率 (ATR)
🎚️ 输出
regime: risk_on / risk_off
multiplier: 0.5x ~ 1.5x
影响后续仓位分配
market_state_daily: date, regime, multiplier, qqq_price, qqq_sma50, ...
↓
5
基线策略 (Baseline Policy)
基于确定性规则生成初始推荐：action (hold/pause/accumulate) + 梯度买入权重。
🎯 决策规则
• Score ≥ 阈值 → accumulate
• Score 中等 → hold
• Score 低 → pause_shallow
📊 梯度权重
ladder_weights_pct:
S1: 10-15%
S2: 15-25%
S3: 25-35%
reserve: 25-65%
⚖️ 市场调整
根据 market_state.multiplier
动态调整 reserve 比例
recommendations_daily: symbol, date, action, plan_json, explain_json, llm_used=0
确定性规则 无 LLM
↓
6
LLM 策略增强 (Strategy Enhancement)
对 MAG7 批量调用 OpenAI，基于融合后的 levels + 市场状态微调策略（保留 baseline 作为 fallback）。
📝 输入上下文
• 融合后的 S1/S2/S3 (来自 Stage 3.5)
• DeepValue Score + Rank
• Market regime + multiplier
• Baseline action + weights
🤖 LLM 任务
批量生成（一次调用多只）：
• 微调 ladder_weights_pct
• 调整 reserve_pct
• 生成 explain (可解释性)
✅ 校验回退
逐条验证 LLM 输出：
• 权重和 = 100%
• reserve ≥ 25%
• 不合规 → baseline_fallback
💡 批量优化
原本逐只调用 LLM（9 次），现在改为批量生成（1 次），大幅降低成本与耗时。
同时保留逐只校验，确保每条策略都符合规则。
# 更新 recommendations_daily UPDATE recommendations_daily SET plan_json = llm_plan, explain_json = llm_explain, llm_used = 1 WHERE symbol=? AND date=?
批量 LLM 逐条校验 Fallback 保护
↓
7
报告生成 (Reporting)
汇总所有计算结果，生成 Markdown 格式的每日报告，展示排名、策略、PP 融合状态。
📊 报告内容
• 市场概览 (regime + top stocks)
• DeepValue 排名表
• 个股详情 (S1/S2/S3 + action + weights)
• PP 融合状态/置信度/区间
🎨 新增列
PP: used(0.78) / ignored(0.00)
PP Band: 260.00-265.00
S1 Src: pp_fused / struct_5y
💾 存储
reports 表 (upsert):
report_id, date, type, content_md, meta_json
# 查看报告 python -m src.reporting.show_report
Markdown 输出 可解释性
内部计算
外部信号融合
